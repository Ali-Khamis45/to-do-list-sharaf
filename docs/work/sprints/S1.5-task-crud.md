## Goal
Implement manual create (idempotent on a client UUID), edit, delete with event cascade, and the lifecycle actions.
Lifecycle actions write task_events with allowlisted fields only. Expose a transaction-aware task service for apply (S2.5).

## Tasks
- [ ] `internal/app/tasks` exposes `Create`, `Update`, `Reschedule`, `Complete`, `Reopen`, `Cancel`, and `Delete`, each taking a `pgx.Tx` so apply can compose them. Document them in the handoff.
- [ ] Compute `title_normalized` with `internal/domain/normalize` and the lifecycle rules with `internal/domain/lifecycle`. Both are read-only uses of Claude Code's packages.
- [ ] Endpoints: `POST /tasks` (`ON CONFLICT (id)`), `PATCH`, `DELETE`, and `complete`/`reopen`/`cancel`/`reschedule`. Each is idempotent on state. Moving a task later increments `defer_count`.
- [ ] The event writer keeps the field allowlist and never writes evidence

## Acceptance criteria
- [ ] Concurrent `POST /tasks` with the same id produces 1 row
- [ ] Rescheduling later increments `defer_count`
- [ ] Completing a cancelled task is rejected
- [ ] DELETE removes the task's events
- [ ] Events contain only allowlisted fields
