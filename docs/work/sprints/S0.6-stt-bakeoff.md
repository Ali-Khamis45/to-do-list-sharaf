## Goal
Run every STT candidate on the 20 clips. Produce per-provider transcript files and a WER/CER, entity, latency and cost table.
The spike is throwaway. Only its outputs are kept.

## Read first
- [architecture-and-ai-pipeline.md](../../architecture-and-ai-pipeline.md) §5.3
- [decisions.md](../../decisions.md) ADR-012

## Tasks
- [ ] `spikes/stt-bakeoff/` is a Python script with one small function per provider. It reads `eval/clips/manifest.csv` and `.env`.
- [ ] Build a vocabulary-biasing prompt per clip. For dev clips, use the case's existing task titles. For held-out clips, use names read programmatically from `.meta.txt`, never displayed.
- [ ] Write `eval/stt/transcripts/<provider>.json` mapping clip id to text, latency_ms and cost_usd
- [ ] Compute WER/CER with `jiwer`. Compute entity accuracy for dev clips from the manifest's `entities` column.
- [ ] `eval/stt/report.md` holds per-provider aggregates for each split, plus per-clip rows for dev clips only
- [ ] `spikes/stt-bakeoff/README.md` states that the spike is throwaway
