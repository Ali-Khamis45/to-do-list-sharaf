# P0: Feasibility & eval harness

Effort: ~62 h (hours are the estimate; we plan by scope, not dates)

## Goal
Prove that an Egyptian Arabic or code-switched night conversation reliably becomes the right checklist, before any UI work.
The output is the pure Go domain core, one LLM adapter, and a one-command eval report on a dev split and a real-night held-out split.

## Scope
- Real-night held-out cases and the dev golden cases, plus 20 audio clips with reference transcripts
- Provider accounts, API keys, and spend alerts
- Throwaway Python STT bake-off
- Go `internal/domain`: dates, normalization, templates, op union, set/clear, evidence locator, dedupe, policy, validator
- Trigram scorer and the measured §7.5.1 fixture
- One `TurnAnalyzer` adapter, prompt v1, and the `cmd/eval` runner with per-split reports
- Gate run, at most 2 prompt iterations, and the D-02/D-03 decision

## Out of scope
- HTTP API, migrations, auth (P1)
- Production STT adapter (P3)
- Any frontend (P3/P4)
- Second LLM adapter, unless the gate is missed (conditional S0.15)

## Exit gate
Copied exactly from [roadmap-and-testing.md](../../roadmap-and-testing.md) §14 (P0 acceptance):

- The eval runs with one command.
- Domain tests are green, including the §7.5.1 fixture and the set/clear cases.
- The STT and LLM choices are recorded in `decisions.md` with numbers.
- **The gate is met on both splits.** If not, iterate the prompt twice. If it still misses, build a second LLM adapter and re-test. If it still misses badly, revisit the approach before any UI work.
