## Goal
Define the golden case file format and labeling guide, and write the 20 dev cases.
Load and validate every case in Go, without ever printing held-out content.

## Tasks
- [ ] `eval/golden/schema/case.schema.json` covers: clock (local ISO and timezone), settings, existing tasks (`T#` alias, title, date, status, priority), pending tray (`P#` and the open clarification), history turns (`U-n`), input text and mode, expected ops (type, target, key fields, resolved date `YYYY-MM-DD`), expected clarification, expected notices, `must_not` rules, and match keywords per expected create
- [ ] `eval/golden/README.md` is the labeling guide: how to label expected ops, titles as spoken, held-out labeling, and the contamination rule
- [ ] Write the 20 dev cases: S1, S2, S3, S4, S5, S7, S8, S9, S11 (two clocks as sub-runs), S12, S13, S14, S15, S17, S20, S22, S23, S26, S29, S30
- [ ] `eval/clips/dev/scripts.md` says what to say for each dev clip. Speak naturally rather than reading verbatim.
- [ ] `internal/eval/golden` loads the cases, validates them against the schema (`santhosh-tekuri/jsonschema`), and detects the split. For held-out cases it reports counts only.
- [ ] Add `make golden-check` and `make golden-freeze` to `mk/ai.mk`. `golden-freeze` writes `eval/golden/heldout/FROZEN.txt` with a date and sha256 sums.
