## Goal
Build the context from the DB, call the analyzer, and run the domain validator.
Persist the run, the items and the assistant message atomically, with templates and reason codes only.

- [architecture-and-ai-pipeline.md](../../architecture-and-ai-pipeline.md) §7.1–§7.5, §7.9

## Tasks
- [ ] `internal/app/analyze` takes a context snapshot: tasks from −1 to +14 days, Later, the pending tray with its open clarification, and the last 10 turns
- [ ] Call `TurnAnalyzer`, then `domain/validate`. Persist in one transaction: analysis_runs with `validation_codes`, proposal_items with evidence offsets, and the assistant message as `llm_reply`.
- [ ] On failure, save a `template_error` message and mark the run `failed`
- [ ] Add the tray summary and the night `dateNote`, and record cost and latency
- [ ] Store no raw model output anywhere
